# 稳定奖励结算与回滚：本地合成验证

日期：2026-09-28。此记录是实现与本地演练，不是生产发奖、真实社区成果或 MVP 放行。

## 已实现的边界

- 新认领原快照锁定稳定 Token、修为、功德；旧认领没有该字段时拒绝补发。
- 维护者不能给自己的成果结算。结算前实时核验两个非草稿、非预发布的 GitHub Release、相隔至少 604800000 毫秒、标签提交在 main 的演进关系中、两版及当前 main 的成果文件摘要都与正式合入摘要相同。记录 release ID、标签、提交、发布时间、核对人和理由；同一成果/认领只结算一次。
- 发现当前 main 摘要变化或成果被移除时，维护者提交回滚证据。原奖励流水不改写；可用余额内追加冲正，已消费部分形成按资源分列的欠账。活动保护性冻结阻止消费、突破和新奖励；未来正向入账优先自动抵债。另一名被单独配置的独立 GitHub 审批人可签署解除保护性冻结；欠账未清时消费与突破继续受限。
- 本人 `/api/me` 和“我的账本”展示冻结、欠账及抵债流水。`ENABLE_STABLE_SETTLEMENTS` 未配置时结算入口保持关闭；生产未配置追回复核人的 ID，不会擅自把已提名的 @Gjts 当作本人接受授权。

## 验证证据

先在真实构建 Worker 上得到 `/api/stable-settlements` 404 红灯，再实现结算；回滚公开 API 也先得到 404 红灯。`node scripts/verify-stable-settlements.mjs` 在隔离本地 D1/Miniflare 中准备合成账号，GitHub 外发被模拟服务接管，不读取模型密钥、不访问真实 GitHub、不写生产：六天间隔拒绝、摘要变化拒绝、满七天并发 8 次仅 1 次成功、旧认领拒绝、作者自审拒绝；随后通过公开购买接口花掉奖励，模拟另两项资源已消费，回滚后得到 10 Token/20 修为/1 功德欠账。后续三资源入账先抵债；余额足够时活动冻结仍阻止购买和炼气突破；第二合成账号独立解除后恢复购买与突破。本人 API 和实际账本 HTML 展示了状态。

本地 `npm test` 为 143 项、142 通过、1 项原有跳过、0 失败；类型检查、lint、构建及上述 Worker/API/D1 驱动退出 0。新 `0015`/`0016` 迁移在隔离 D1 顺序应用；没有对生产 D1 执行这两项迁移。完整回归和远端 CI 仍需随草稿 PR 复核。

## 上线前仍需
