# 独立复验工作台验证

开始日期：2026-09-30；最终本地浏览器核对：2026-10-01。
固定远端基线：`40d8180f3b9b0573a6deb3314ad7176156cc7370`。

## 完成的实现

- GitHub 登录修士可以进入 `/revalidations`，选择其他人的正式成果，查看固定提交、摘要和报告草稿，并提交报告 PR 与专用复验运行的地址或编号。
- 草稿中的验证器基线和观察内容留空，必须依据实际报告 PR 和复跑观察填写；页面不会生成已完成复验的证明。
- 可选成果要求 `accepted` 提交、`completed` 认领、`done` 悬赏及合入时间，并校验原契约。本人作品、已有待审或已采纳复验不会重复进入表单；驳回后允许依据新的可信运行重提。
- 修士只看到自己的报告历史；维护者在 `/review` 处理待采纳报告。原成果作者与复验人均不显示采纳控件，服务端仍再次校验独立身份和当前 GitHub 证据。
- 有效的失败复跑仍可采纳。采纳只影响现有独立复验资格，不增发游戏 Token、修为或功德。
- 复验理由沿用普通复核的凭据形状检查。网络状态不明时表单保留内容并提示先核对记录；错误仓库或无效编号有输入说明。
- 修正 `body` 的固定最小宽度：`min(320px, 100%)` 为滚动条留出空间。修正前 320 像素视口的可用宽度为 305，而正文宽度为 320，实际存在 15 像素横向滚动；修正后按页面可用宽度验证。

## 验证与复现

在包含本次源码与验证脚本的副本中执行：

```sh
cd site
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run typecheck
npm run lint
npm run build
node scripts/verify-revalidations.mjs
```

- 普通测试：143 项，142 通过、1 个原有跳过、0 失败；类型、lint 和构建退出码 0。
- 凭据理由测试先在旧构建上失败：接口返回 200，预期 400；补齐检查后的实际构建/API/D1 回归通过。
- 新页面回归覆盖匿名登录提示、原作者没有提交表单、待审目标消失、私有记录隔离、维护者采纳入口、维护者兼原作者回避、驳回重提及采纳后的历史。
- 保留既有固定来源变化、旧运行拒绝、失败复跑采纳与 20 次并发决定只落一次的检查，合成账本 Token 仍为 0。

浏览器验证使用同一脚本的本地模式：

```sh
node scripts/verify-revalidations.mjs --browser
```

脚本输出仅监听 `127.0.0.1` 的地址。访问 `/fixture/sign-in?actor=reporter`、`adopter`、`author` 或 `outsider` 使用合成身份；PR 7 / 运行 99 是被外发模拟器替换的测试来源。该登录入口只存在于验证脚本，不属于发布路由。

实际浏览器完成键盘提交、维护者鼠标采纳和结果页读取；错误凭据理由被拒绝并保留原输入，错误仓库地址使表单无效并显示说明。页面无浏览器错误。320 × 850 布局核对结果：复验页、首页、装备页均为 `clientWidth = scrollWidth = 305`，账本页均为 320；采用页面可用宽度而非只与 `innerWidth` 比较。
