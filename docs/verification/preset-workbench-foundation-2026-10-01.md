## 本地验证结果

`npm test`：154 项，153 通过、1 个原有跳过、0 失败。`npm run typecheck`、`npm run lint`、`npm run build` 均退出 0。新增 7 项覆盖：

1. HTTP 导入写入与 Runner 相同的修士本机存储；基础槽位满时拒绝；Runner 直接读取同一预设的更严格输出参数。导出只有四个允许字段，不导出身份、路径或任务快照。
2. 读取及写入都需要本次随机会话凭据；错误 Host、跨站 Origin、跨站 Fetch Metadata 和缺少凭据均拒绝。写入还必须有精确本机 Origin；删除必须明确确认同一编号。
3. 疑似密钥、不支持字段、命令或扩大的输出上限拒绝；8 KiB 上限、JSON 格式与媒体类型执行前检查。拒绝响应不回显输入或凭据。
4. 卸下传功玉简后，额外功法仍能导出备份，但 Runner 不能启用超出基础槽位的预设。
5. 删除仅移除明确选中的预设，不删运行历史；错误编号或未确认删除不改记录。
6. 任务包到期后不能继续管理；原预设保留，不刷新租约或模型额度。
7. 本机记录损坏时保留原文件，错误不回显正文和私密路径，提示先刷新核对结果而不是盲目重试或删除锁。

首轮拒绝测试出现一次 `200 != 403`：Node fetch 将测试提供的伪造 Host 替换回正确的本机 Host，原始 HTTP 回显诊断确认了这一点。测试改用原始 HTTP 后真正发送伪造 Host，七项全部通过；没有修改运行时防护或放宽断言。

所有预设、身份、文件、账本历史和会话均为隔离本地合成数据，不产生真实模型请求。测试关闭各自 HTTP 服务并只清理经过路径确认的临时目录，不改用户真实预设、检查点或私密环境配置。
