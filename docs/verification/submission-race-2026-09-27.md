负对照只在复制到内存的一个构建模块中去掉“本次提交已成功入库”的 `EXISTS` 条件，并恢复相应的三参数绑定；先断言匹配唯一，匹配失败立即停止，不泛化修改任意模块。负对照确实违反当前“不允许无待审成果却进入审核”的断言；它不是修复后的代码，也没有写入用户源码或原构建文件。两组 HTTP 都可能返回 429，所以只看返回码不足以证明修复，必须同时检查认领、成果与 R2 状态。

每组都实际观察两次 R2 写入和一次失败对象删除；四个既往失败对象由隔离准备过程直接写入。仅覆盖这一确定交错与零押金释放，不代表所有提交上限、账号隔离、存储故障、押金退款或生产网络情况均已验证。
