# Issue 与发布审查来源

本仓库使用 GitHub Issues。配置依据是本机当前 `origin` 的主机与仓库路径：`github.com/HardieBao/lingnet-ascension`；没有凭据嵌入该远端地址。这个映射不证明 Issue 已批准、远端已包含本地实现或任何任务已完成。

## 查阅

收到明确的 Issue 编号时，读取该 Issue 的正文、验收条件、允许路径、预算、依赖和状态，再按贡献指南核对。可使用已有 GitHub 只读工具或 `gh issue view <编号> --repo HardieBao/lingnet-ascension`。不得自动创建、修改、评论、关闭 Issue 或扩大允许路径；外部写入仍须符合用户已授权的具体工作流。

没有编号时，不从本地文件名、分支名或任务代号猜测编号。当前 MVP 的本地规格来源为根目录 `plan.md`、`task.md`；发布证据另见 `MVP_RELEASE_GATES.md`。贡献规范为 `CONTRIBUTING.md`，代码修改仍执行用户的四个原则和 GitNexus 检查。

## 工作区与审查

本地未提交源码、独立测试和合成快照不等于已批准 Issue 的真实成果。需要维护者明确关联任务与批准范围，不能伪造认领、签署、独立复核或社区贡献。

正式双轴审查应使用已确认的固定基线和包含当前候选内容的不可变审查快照；未提交工作必须明确包括必要的未跟踪文件。不得用空的提交区间声称审查通过，也不得为了准备快照改写用户的暂存区或丢弃现有改动。

该文档补充原先缺失的 tracker 映射，不启用生产角色、奖励结算或任务解锁，也不代表已经完成 code-review 技能的双轴审查。
