## 本地运行

需要 Node.js 22.13+。在本目录执行：

```sh
npm ci --ignore-scripts
npm run build
```

首次使用本地 D1 时，按文件名顺序执行 `drizzle/` 下尚未执行的迁移。示例：

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_spotty_tomorrow_man.sql
```

然后执行 `npm run dev`，打开终端显示的本地地址。Windows PowerShell 可把命令中的 `npm` 换成 `npm.cmd`。本地开发的 `/signin-with-chatgpt?return_to=/` 是 Sites 模拟身份，不代表生产 GitHub 登录已完成。`.wrangler/` 和 `.sites-runtime/` 为忽略的本地状态，不要提交。

生产 GitHub 会话必须由托管环境私密提供 `SESSION_SECRET`（至少 32 个字符），并配置 GitHub OAuth 的客户端信息。缺少密钥时签名会话会被拒绝；源码不包含开发密钥回退。个人 `.env*` 和 `.dev.vars*` 已忽略，勿把凭据写入仓库或 PR。

- 当前租约心跳受品阶绝对时限约束（黄阶 2 小时、玄阶 6 小时、地阶 16 小时、天阶 72 小时），每次续期最多 2 小时。文档上传限单次认领 5 次、同一用户对同一任务累计 10 次“需修改”；达到上限返回明确提示，由维护者人工处理。这个按账号的限制不能代替部署层面对多账号攻击的限流。
- 任务初始化检查五张种子悬赏及其依赖；已就绪时不再重复种子插入。预算升级仅为尚未声明额度的开放/锁定悬赏补充未来认领额度，不重写历史认领。前置成果正式合入时，同一事务更新后续任务的开放状态。
- GOV-004T 是 GOV-004 拆出的单文件 Token 条款任务，与 GOV-002 一样在 GOV-001 正式合入后解锁，可由另一位修士并行认领。它不替代仍待确定的代码许可证、资源许可或正式法律审查。
- 新认领下载 v4 任务包：固定 `gpt-5.6-sol`，30,000 总模型 Token / 单请求 2,048 输出，重试和恢复共用余额；带修士绑定及当前装备的检查点/预设参数，不修改旧认领快照。旧 v3 有限额任务仍可执行但没有新增槽位功能，旧 v2 无预算任务只允许离线预检，原 `--ack-unbounded-usage` 已停用。
- 正式 Runner 使用本机 Docker 隔离 CLI 和可信限额网关。把 `runner.mjs`、`runner-sandbox.mjs`、`runner-workspace.mjs`、`budget-gateway.mjs`、`runner-checkpoints.mjs`、`runner-presets.mjs`、`runner.Dockerfile` 七个文件放在同目录，运行 `node runner.mjs doctor`，按提示准备镜像。模型工作区使用 64 MiB 容器临时盘，任务基线与 Git 元数据只读；仅导出通过范围、普通文件和 128 KiB 检查的成果，不导出整个目录。模型容器关闭持久日志和交换额度，导出前断网并清除后台进程；失败不补模型额度或延长租约。密钥从本机私密环境配置 `OPENAI_BASE_URL` / `OPENAI_API_KEY`（或 `LINGNET_MODEL_BASE_URL` / `LINGNET_MODEL_API_KEY`）读取，只交给可信网关，不交给执行容器或平台；不要把真实密钥放进命令参数。
- 只有代理部署的准确计数、输出上限（含推理）和收费边界均已独立核验，才可记录运维放行 `LINGNET_PROVIDER_LIMITS_VERIFIED=1`，再运行 `node --env-file=.env.local runner.mjs run <任务包.json> --ack-model-costs`。标志本身不是技术证明，**当前真实代理未完成验证，不要为绕过提示而设置**。本地模拟服务通过不代表第三方严格限额；模型 Token 也不是现金上限。
- `.lingnet/budgets/<认领 UUID>/` 保存独立额度与互斥锁，执行容器不可访问；刷新任务包、重跑和网关重启不补额度。CLI 在只读根目录、只读 Git 元数据、内部网络、非特权和资源限制下运行；异常用量保留预留并停止。没有正常关闭的锁需人工核对，不能直接删除锁或预算记录后重跑；重新认领属于新的独立预算与费用决策。
- Runner 在实际启动模型前创建本机 `.lingnet/runs/<运行 UUID>/started.json`，进程退出后追加一次 `finished.json`。记录绑定认领、悬赏、任务包摘要和固定基线，只保留时间、模型进程状态、可选预设的数字参数及经过校验的数字用量；不保存原始对话、提示词、错误正文或环境变量。不能从当前事件可靠确定模型名称时记为 `null`。这些本机记录不是平台可信计费凭证，不发放奖励；可恢复成果另存检查点目录。
- CLI 用量标为 `codex-cli-reported` / `reported-turn-only`，不是费用账单；新增 `local-capped-gateway` 数值回执分别记录额度、已核验用量、剩余、预留及停止状态。均为用户可修改的本机记录，不作为服务端可信计费凭证，也不发游戏奖励。没有有效 CLI 完成事件时记为 `unknown`；未知预留不能当作零费用。`model-completed` 仍需范围检查、独立审判、复核和合入，不等于正式成果。
- 检查点按每位修士在本机共用：基础 1 槽 / 24 小时，储物袋后 2 槽；护心符每认领首次失败可延长一次至 48 小时，不延长租约。只保存通过范围/大小/凭据形状检查的限定单文件成果，不保存私人模型会话。恢复是固定基线上的成果重建，再启动新 CLI；每个检查点仅一次、认领互斥、继续原额度，不解锁未知用量或退模型费。卸装不自动删除已有缓存，满槽时需明确舍弃；过期清理只处理缓存，不删除原成果。扫描不是无秘密保证。
- 功法预设按修士本机基础 1 槽，传功玉简后 2 槽；仅允许名称、推理档位、补充提示和不超过 2,048 的更严格输出上限，不保存密钥、自定义命令或总预算覆盖。卸装后额外预设保留但不可启用。检查点和预设分别位于 `.lingnet/checkpoints/<修士 ID 的 SHA-256>/` 与 `.lingnet/presets/<同一摘要>/`，避免 GitHub 身份中的冒号成为 Windows 路径。

## 双人调账（默认关闭）

本地代码提供 `POST /api/token-adjustments` 申请、`POST /api/token-adjustments/:id/decision` 审批和 `GET /api/token-adjustments` 查看最近记录。申请字段为 `targetCultivatorId`、非零整数 `delta`、业务 `reference` 和 20–500 字理由；审批字段为 `decision`（`approve` 或 `reject`）及理由。批准会由 D1 触发器在同一事务中追加一笔 `token` 流水；驳回不改账，余额不足会回滚审批。

只有在托管环境分别配置两个**不同的 GitHub 数字用户 ID**：`MAINTAINER_GITHUB_ID` 与 `FINANCE_APPROVER_GITHUB_ID` 时，申请与审批入口才会开放；用户名不是数字 ID，同一账号填两处也不会开放。模型费用与模型 Token 不属于此接口。拟任审批人尚未本人确认职责，且缺少两个真实账号的上线演练，不应在生产环境配置第二审批人或执行调账。

指定账号可在 `/economy` 操作：申请人选择目标修士、填写金额、唯一业务引用和证据；审批人填写独立复核理由，通过确认框批准或驳回。页面只显示最近 50 笔记录；失败时保留草稿，重试前应核对记录以避免误认为第一次请求没有完成。2026-09-27 的隔离演练覆盖正常批准、重复申请/审批、驳回、超额扣减、权限隔离与手机长理由确认；使用合成身份和独立本地 D1，不是生产签署或正式社区成果。

| `POST /api/trials/:id/finish` | 渡劫本人；本次成果必须按时形成正式合入记录、由另一账号复核、与认领基线一致；再次校验门槛，成功后结算已冻结费用并突破契约目标（筑基或金丹）。重复请求不会再扣费或突破。 |
| `POST /api/trials/:id/withdraw`，`{ reason }` | 渡劫本人；1–500 字理由，全额退还渡劫费用，保留记录。仅退出渡劫绑定，原悬赏认领仍保留；释放认领及任务押金继续走原释放流程。 |
| `POST /api/trials/:id/abort`，`{ reason }` | 指定维护者；记录确认人和至少 20 字的平台故障证据，只能中止尚无正式成果的进行中渡劫，全额退款。 |

开始参数、基线、费用和期限不能改写；终态只允许写入一次且历史不能删除。冻结、解冻与突破由数据库触发器在同一写入中执行；补结算使用 [D1 批量事务](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)的整批失败回滚语义。境界查询和登录后的首页会补结算当前修士；自定义 Worker 现在也提供 `scheduled` 平台入口，沿用同一成功优先的事务。单个账号失败不阻断其他账号，处理后整体报告异常以供重试。每五分钟Cron已实际部署并读取复核配置，但真实渡劫结算、执行日志与异常告警尚未验收，不用配置声明代替运行证据。

读取响应的 `offers` 最多两项，只包括本人有效、已开跑、未提交、匹配当前境界的专属认领；已用于渡劫的认领及本人已有进行中渡劫时不再列出。`entry` 只评估开始前的资源/正式成果/复验门槛，不表示已通过渡劫；`next` 仍要求渡劫通过。资格满足也可能没有匹配契约，候选契约存在也可能资格不足，开始接口仍以事务内完整检查为准。金丹后 `entry` 为 `null`，历史仍可读取。

## 独立复验与采纳后端（尚未公开）

复验报告只允许 `revalidations/<原成果提交 UUID>.json` 一个文件；固定版本、原提交编号、悬赏、原文件路径、合入 SHA、文件 SHA-256、可信验证器基线 SHA、复验人的 GitHub 数字 ID 与 20–2,000 字观察记录。`lib/revalidation-report.ts` 从任务契约推导文档/代码类型，不执行报告提供的命令；报告不得包含密钥或私人信息。

专用 `revalidation.yml` 使用 PR 基线上的可信检查器，重新检出指定的已合入提交，核对原文件摘要后执行复验，不把报告分支当作目标源码。文档执行已有结构检查；代码使用只读、无网络、非特权容器进行完整回归。结果区分 `Replay passed` 与 `Replay failed`：复跑发现失败仍可成为待人工采纳的证据，但设置错误、报告越界、摘要不匹配或无法启动验证不算有效复验。普通 CI 对报告只做结构路由，绿色结果本身没有资格或奖励。

`lib/revalidation-source.ts` 核对报告 PR 作者、单文件范围、当前报告提交、专用工作流、运行代次及唯一的可信结果标记，再核验原成果仍在 `main` 且摘要一致。文件范围来自固定基线与头提交的比较，不使用可在读取之间变化的 PR 文件清单。工作流使用可信 `run-name` 绑定 PR 编号；不能只依赖 `pull_requests` 数组非空。[GitHub 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request)区分 PR 头提交与合并测试提交，两者不能混为一个来源。

应用新增 `0012_nasty_the_stranger.sql` 后，后端提供以下接口。原作者不能自复验；采纳人必须是配置的 GitHub 维护者，且与原作者、复验人均不同。

| 接口 | 作用 |
|---|---|
| `POST /api/revalidations`，`{ submissionId, pullNumber, runId }` | GitHub 修士提交另一个作者的正式成果复验；观察记录与结论从专用可信运行和报告获取，不接受请求直接宣称“通过”。 |
| `GET /api/revalidations` | 修士只读自己的最近 50 笔记录；指定维护者可读待运营复核的记录，私密且不缓存。 |
| `POST /api/revalidations/:id/decision`，`{ decision, reason }` | 维护者选择 `accept` 或 `reject`，填写 8–500 字理由。采纳前重新核对头提交、报告内容、原成果摘要、运行代次与结论。 |

证据和决定均不可改写或删除。待审和已采纳报告阻止同一修士对同一成果再次提交；驳回后需新的可信运行编号重试，旧证据和理由保留。不同修士可以各自复验同一成果；某位修士的资格按不同悬赏去重，仅统计已独立采纳且原正式证据仍与记录相符的复验。有效的失败复跑也可由维护者采纳为复验贡献。此通路只计资格，**不自动发放游戏 Token、修为或功德**；金丹开始和成功结算均校验此资格，真实契约与操作入口仍未公开。

`node scripts/verify-revalidations.mjs` 在独立临时环境运行实际构建后的接口和本地 D1，拦截所有应用外发请求并使用合成 GitHub 响应；需先 `npm run build`，不读取模型密钥。测试覆盖来源不匹配、自复验、自采纳、原作者兼任维护者、权限隔离、报告头/运行变更、驳回重试和二十次并发采纳；完成后关闭模拟器并删除本次临时数据。它不属于普通 `npm test`，也不能证明真实 GitHub 工作流、真人采纳或正式成果。文档复跑 CLI 已在临时 Git 仓库实测；完整代码复跑 CLI 也已在合成仓库验证正常代码通过、固定代码回归失败及摘要错误拒绝，详见[本地复验记录](../docs/verification/code-revalidation-cli-2026-09-27.md)。远端专用工作流、真实成果复跑和独立采纳仍缺实际证据，操作页面尚未提供。

## 贡献与自动检查

本地新增复核租约与敏感凭据隔离回归：先构建，再分别运行 `node scripts/verify-review-lease.mjs`、`node scripts/verify-artifact-quarantine.mjs`、`node scripts/verify-code-quarantine.mjs`。它们在合成本地 D1/R2 运行实际 API，GitHub 响应只在测试外部边界模拟，未调用模型或读取 `.env.local`。验证累计租约、冻结/独立修订/押金一次退款、对账与席位，以及清理后正常投稿；数据保留于命名的系统临时目录，模拟器结束后关闭。

命中疑似密钥、私钥或私人配置凭据的文档/代码成果进入 `frozen`，摘要与安全原因保留，原文不存入 D1 成果表，也不可下载。普通过期、释放、上传和批准不会自动解除；独立维护者可通过原复核接口选择 `revise`（期限内允许重新上传）或 `reject`（驳回并退还原押金），记录理由。该接口也拒绝含凭据的理由。冻结的操作界面和来源/许可流程仍待实现；规则扫描不能证明所有秘密或资源授权均已清除。详见[本地修补验证](../docs/verification/lease-and-quarantine-2026-09-27.md)。

当前成果存储采用 D1：不超过 128 KiB 的 UTF-8 文档及有界代码 PR 元数据与提交状态同批次写入，读取核对字节上限和 SHA-256，保持作者/维护者权限。`0014_d1-artifact-payloads.sql` 新增关联提交的载荷表。可选 `BUCKET` 只读旧 R2 对象，不新增写入；旧生产对象不自动迁移。`node scripts/verify-d1-artifacts.mjs` 无 R2 绑定验证上传、精确 BOM 字节、权限、独立复核、合入及奖励仅一次；`node scripts/verify-d1-submission-race.mjs` 暂停上传事务，先释放认领，再验证过期事务不能插入提交或载荷。均使用实际本地 D1 与合成身份，不证明真实社区成果。

旧 `verify-submission-race.mjs` 和[旧并发记录](../docs/verification/submission-race-2026-09-27.md)属于 R2 写入版本的历史证据，不适用于当前 D1 存储，不应计作当前通过项。当前检查点、预设、装备与存储证据见[本轮验证记录](../docs/verification/checkpoints-presets-d1-2026-09-27.md)。
